# Contributing to Mosca Tee

Thank you for your interest in contributing to Mosca Tee! We welcome contributions from the community that help us build a better, more accessible graphic editor for everyone.

## How to Contribute

### Reporting Bugs

If you find a bug, please open an issue with:
- A clear, descriptive title
- A detailed description of the problem
- Steps to reproduce the issue
- Expected and actual behavior
- Your environment (OS, browser, etc.)

### Suggesting Enhancements

We love feature suggestions! Please open an issue with:
- A clear, descriptive title
- A detailed description of the enhancement
- Why this feature would be useful
- How it might be implemented (optional)

### Accessibility Improvements

Since accessibility is core to Mosca Tee, we especially welcome contributions that:
- Improve screen reader support
- Enhance keyboard navigation
- Add or improve accessibility documentation
- Test with actual accessibility tools

### Code Contributions

1. Fork the repository
2. Create a feature branch (`git checkout -b feature/amazing-feature`)
3. Make your changes
4. Test thoroughly (especially accessibility features)
5. Commit with clear messages (`git commit -m 'Add amazing feature'`)
6. Push to the branch (`git push origin feature/amazing-feature`)
7. Open a Pull Request

## Development Setup

```bash
# Clone and install
git clone https://github.com/moscatee/mosca-tee.git
cd mosca-tee
npm install

# Run development server
npm run dev

# Build for production
npm run build

# Type checking
npm run lint
```

## Code Style

- Use TypeScript for new code
- Follow existing code patterns and naming conventions
- Format code with Prettier (configured automatically)
- Write meaningful commit messages

## Accessibility First

When contributing, please consider:
- Can blind users navigate this feature?
- Are keyboard shortcuts available?
- Is screen reader output clear and useful?
- Does the WCAG contrast meet AAA standards?

## Pull Request Process

1. Update documentation if needed
2. Add tests for new features
3. Ensure all tests pass
4. Describe what your PR does and why
5. Link related issues
